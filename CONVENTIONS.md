# JavaDoc conventions

## Follow grammar conventions

Use American English spelling.

Use terminology consistent with Minecraft and nearby documentation.

Preserve capitalization and spelling when referring to code.

```diff
-/// leap over nearby fops when not attacking something
+/// Jump over nearby foxes as long as `this` is not aggressive.
public void jumpOverFoxes() { /*...*/ }
```

## Add value

Explain only what a developer cannot learn from the member's declaration. Leave obvious members undocumented.

Document only what a caller needs to know. Don't walk through implementation.

```diff
-/// Gets the width.
+/// Returns the width in pixels.
public double getWidth() { /*...*/ }

-/// Returns the id of this object.
public Identifier getId() { /*...*/ }
```

## Start with a summary

Write a concise first sentence that can stand alone. For methods, start with a verb such as "Returns," "Sets," or "Removes." Add a blank line before further explanation (if any is required).

```diff
+/// Iterates over a column of blocks, then over all its neighbor columns.
+/// 
/// Iterates from `(startX, startY, startZ)` until `y==endY` (exclusive), then does the same for each of the columns on the north, east, south, and west of the first column. Iterates upwards if `startY<endY`, downwards if `startY>endY`.
public static Iterable<BlockPos> neighborColumn(int startX, int startY, int startZ, int endY) { /*...*/ }
```

## Use Markdown format

Use backticks (\`) for identifiers, literals, and short expressions. Separate paragraphs with blank lines. Prefer Markdown lists and fenced code blocks over HTML. Use markdown links instead of `{@link}` or `{@linkplain}`.

When linking to a member of the same class, use `#` (such as `[#clear()]`).

For syntax reference, see [Oracle's JavaDoc Guide](https://docs.oracle.com/en/java/javase/25/javadoc/using-markdown-documentation-comments.html).

```diff
-/**
- * Returns a random integer generated by <a href="https://github.com/FabricMC/community/blob/main/images/tinypotatoinafield.png" Tiny Potato>. {@code 4} is weighted more heavily than any other number.
- * 
- * Also see {@link ThisClass#veryBadNumber()}.
-**/
+/// Returns a random integer generated by [Tiny Potato](https://github.com/FabricMC/community/blob/main/images/tinypotatoinafield.png). `4` is weighted more heavily than any other number.
+/// 
+/// @see #veryBadNumber()
public static int veryGoodNumber() { /*...*/ }
```

## Explain parameters and return values only when needed

Use `@param`, `@return`, and `@throws` when they help the reader better understand a method's usage. Information may be repeated from the rest of the JavaDoc. **Use short phrases without an inital capital or final period.**

Document only the parameters of a method that need explanation. A method may have both documented and undocumented parameters.

Take special care to document special parameter cases (such as using `-1` to indicate no limit). 

Use `@throws` to explain a relevent failure condition, not to list every exception that could be produced.

```diff
+/// ...
+/// @param namespace the namespace, restricted to `[a-z0-9_.-]`
public static Identifier fromNamespaceAndPath(String namespace, String path) {/*...*/}

+/// ...
+/// @param timeout the maximum wait in milliseconds, or `-1` to wait indefinitely
public void waitForEndUpdate(long timeout) {/*...*/}
```
